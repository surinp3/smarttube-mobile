# SmartTube phone ↔ Google TV sync on Bunny

This service uses **Bunny Database** and a standalone **Bunny Edge Script**.
No Supabase service or credentials are used. The database is private, and the
Android applications communicate only with the Edge Script's public HTTPS URL.

## What is synchronized

- Local Rumble channel follows and channel sort order.
- The chosen video source: YouTube, Rumble or Both.
- TV sidebar sections and pinned YouTube/Rumble channel order.
- App-managed resume positions, with the provider and video ID attached.

Existing signed-in YouTube subscriptions continue to be managed by YouTube;
the sync service never stores YouTube tokens or Google credentials. Playback
state generated by YouTube remains authoritative for YouTube videos.

## Provisioning (Bunny account required)

1. In the Bunny dashboard, create a dedicated **Database** such as
   `smarttube-pat-sync`.
2. Apply [`schema.sql`](schema.sql) through the Bunny Database editor (or
   put it in a Bunny CLI migration). This creates isolated sync tables.
3. Create an **Edge Platform → Scripting → Standalone** script. On the
   database's **Access** page, generate a **Full Access** token and use
   **Add Secrets to Edge Script**. This supplies `BUNNY_DATABASE_URL` and
   `BUNNY_DATABASE_AUTH_TOKEN` to Bunny's server environment.
4. On the Edge Script add an environment **secret** named
   `BUNNY_SYNC_SETUP_CODE`: choose an unguessable string of at least 20
   characters. This is entered **on the phone once**, never on TV and
   never committed to GitHub. Treat it like an account-recovery secret.
5. On GitHub `surinp3/smarttube-mobile`, set repository Actions secrets
   `BUNNY_SYNC_SCRIPT_ID` and `BUNNY_SYNC_DEPLOY_KEY` using the script's
   **Deployments → Settings** values. Do not put database tokens here.
6. Run GitHub Actions **Bunny sync service** on `main` with `deploy=true`.
   It runs tests, bundles the Edge Script and publishes only after success.
7. Open `<your public Edge Script HTTPS URL>/health`. Expected response:
   `{"ok":true,"service":"smarttube-bunny-sync","version":1}`.
8. Edit the public, non-secret `sync_config.json` in the GitHub repo to:
   `{"enabled":true,"edgeScriptUrl":"https://your-public-edge-script"}`.
   **Do not publish the `libsql://` database URL**, or any authentication
   token in that file. The TV will discover this HTTPS endpoint automatically.
9. To enable Rumble video discovery and playback, set the **Edge Script** secret `APISH_KEY`
   to your paid/free-tier API.SH Rumble provider key. This key stays on Bunny,
   never in the APK. The backend caches feed searches for an hour and limits
   uncached requests (including video detail lookups when playback starts) to
   30 per UTC day to control provider usage. No Rumble
   key means YouTube still works, but Rumble feed discovery reports an error.

The public **HTTPS Edge Script URL** (not the private `libsql://` database
URL) is read by both Android apps from `sync_config.json`. The phone can also
enter or change the HTTPS URL in Settings. Until the public URL is configured,
the server is deployed, and a provider key is set, the apps must not claim
that Rumble cloud feeds and sync are active.

## Secure pairing protocol

Only the phone needs the one-time server setup code. It exchanges that code
over HTTPS for a random, **device-specific** token (`/v1/device/bootstrap`).
The server saves only a SHA-256 hash of the issued token.

On the TV:

1. TV calls `POST /v1/pair/start`, receiving a one-time 10-digit pairing
   code, a pending device token and a five-minute expiration.
2. Phone, already authorized, calls `POST /v1/pair/approve` with the code.
3. TV polls `GET /v1/pair/status` with its pending token. Once approved,
   that token becomes its own authorized device token.

No Bunny database token, phone token or setup code is ever entered on TV.
Only random per-device tokens are stored inside each app's private storage.
The setup code can be used to register a replacement phone if a device is
lost. Rotate the setup code if it is exposed.

## Sync state and conflict handling

`GET /v1/state` returns `{ revision, state, updatedAtMs }`. The state has
only four whitelisted fields: `sourceFilter`, `channels`, `sidebar`, and
`progress`. All channel IDs are tagged with the `youtube` or `rumble`
provider, and sidebar entries may additionally use `section`.

`PUT /v1/state` sends `{ revision, state }` using optimistic concurrency.
If another device wrote in between, the server returns HTTP `409` with
the newer revision and full current state. Apps **must merge** the remote
changes with their pending local edits and retry; never overwrite a newer
revision or drop local edits without notifying the user. The server limits
payload sizes and accepts no secrets or unrecognized fields in the state.

The database never handles video media or streaming; it stores only the
user's own channel and progress preferences. Rumble feed discovery remains
a separate integration, with its own provider credentials and availability.
Search results provide cards but often omit media URLs. Opening a Rumble card
calls the authenticated `/v1/rumble/video?url=...` endpoint to obtain HLS and
MP4 alternatives, cached briefly. The Android ExoPlayer receives media URLs
only, not the provider key or Bunny database credentials. Playback requires
an internet connection and working third-party media/CDN endpoints.

## Tests

Run `node --test bunny-sync/tests/handler.test.mjs` on Node 24+. The tests
use the built-in SQLite implementation with the same schema and validate
pairing, token access, stale-write protection, expiration and payload rules.
